# Requirements

  Linux, GCC 15.2.0 gnu17 is used, sources for C++17 or later
  Tested under Ubuntu 26.04 LTS for WSL Linux 6.18.33.2-microsoft-standard-WSL2
  Tested under Ubuntu 24.04.4 LTS for Docker (shares the WSL2 host kernel)

# Build instructions

  These instructions are for several cases (scroll to whichever one applies to you)
- Linux (under WSL2)
- Windows subsystem for Linux with Microsoft Visual Studio Community 2022
- Docker Desktop for Windows with Linux container

## Build for Linux (WSL2)

- Install applications from apt:
sudo apt install -y build-essential cmake gdb gdbserver python3-pip ninja rsync openssh-server
- Install conan from pip:
pip install conan --break-system-packages
- Setup conan:
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
conan --version
  (check that the version is 2.x)
conan profile detect
  (check that conan detected compiler.cppstd=gnu17 or later)
- Place sources in some folder, for example:
  /mnt/c/linux/binance_aggregator
- Run conan:
conan install . --build=missing -s build_type=Debug
  or
conan install . --build=missing -s build_type=Release
  (this must download and build all external libraries in build/Debug and build/Release folders)
- Run cmake configuration:
cmake --preset conan-release
 or
cmake --preset conan-debug
- Run build:
cmake --build build/Release
 or
cmake --build build/Debug
- Run application (from project folder)
build/Release/binance_aggregator
 or
build/Debug/binance_aggregator
- Wait about 10-20 secs
- Stop it with ^C
- You can look at the generated log:
cat aggregator.log
- Or look at the larger sample log:
cat aggregator_log_sample.txt
- Run tests:
build/Release/unit_tests
 or
build/Debug/unit_tests

## Build for Visual Studio Community 2022 and WSL2

- In WSL2 console install applications from apt:
sudo apt install -y build-essential cmake gdb gdbserver python3-pip ninja rsync openssh-server
- Install conan from pip:
pip install conan --break-system-packages
- Setup conan:
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
conan --version
  (check version is 2)
conan profile detect
  (check conan found compiler.cppstd=gnu17 or later)
- Place project files on Windows disk like:
  C:\linux\binance_aggregator
It will be visible in the Linux here:
  /mnt/c/linux/binance_aggregator
DO NOT place project files on Linux disk (including user home)
This causes Visual Studio to freeze while trying to lock files in the .vs folder
- Go to binance_aggregator folder, run:
./conan_install
  (this must download and build all external libraries in build/Debug and build/Release folders)
- In Windows 
- Do not forget to install the package 
  "Linux / macOs / embedded development"
  for Visual Studio Community 2022 
- Run Visual Studio, select "Continue without code"
- Turn off auto-configure for CMake:
  Tools -> Options -> CMake -> General -> CMake configure step -> Never run configure step automatically
- In the main menu select: File->Open->CMake... C:\linux\binance_aggregator\CMakeLists.txt
- In the main toolbar select "WSL: Ubuntu", "conan-debug (no source copy)" or "conan-release (no source copy)"
  If there are no such choices, exit from Visual Studio, re-run conan_install, re-enter Visual Studio
- In the Solution Explorer select CMakeLists.txt and run **ONCE** "Configure binance_aggregator"
- **DO NOT RUN "Delete Cache and Reconfigure"!**
  In this case Studio will delete files generated by conan and you must re-run conan_install
- **DO NOT RUN "Configure..." twice!**
  In this case Studio will also delete files generated by conan (it is not fully compatible with WSL2)
  To re-configure, run again conan_install and once "Configure..."
- After configuration, use main menu: Build->Build All
- In the main toolbar select runnable "binance aggregator"
- You can set run options here to select current directory the same as the config files. 
  I recommend just copying 'settings.ini' and 'fixed_settings_for_test.ini' to build/Debug or build/Release.
- Run application
- To stop it, press ^C in Remote Console
- To run tests, use main menu to open View->Test Explorer and press double green icon ">>"

## Build for Docker Desktop (for WSL2)

- Install and run Docker Desktop: https://www.docker.com/products/docker-desktop/
- Set up Docker Desktop: Settings/Resources/WSL Integration, turn on Ubuntu
- In WSL2 console in Ubuntu add yourself to the docker group:
sudo usermod -aG docker $USER
- Restart WSL2 console
- Place sources in some folder, for example:
/mnt/c/linux/binance_aggregator
- Or remove all sub-folders like 'build' and '.vs' if sources are already placed.
- Create a container
docker compose up -d --build
- Run steps for Linux case above from "Run conan" step
- Exit the docker console:
exit

# Architecture Overview

## The binary binance_aggregator uses these libraries

- nlohmann_json::nlohmann_json -- for JSON parse
- spdlog::spdlog -- for logging
- ixwebsocket::ixwebsocket -- for implementation of WebSocket 
- GTest::gtest -- for unittests

## Configuration file

File settings.ini is an example config for running app and experiments.
File fixed_settings_for_test.ini is a fixed version used only for tests.
Since the task explicitly says not to spend time on exhaustive config validation,
and '.ini' has no single formal standard anyway, this implementation 
is intentionally minimal: 

No comments, no whitespace, but just several lines in format:
key=value
followed by a line:
streams=
and stream names in lower case

By default binance_aggregator uses settings.ini in current folder.
To use different config file specify it as single argument of binance_aggregator.

Possible keys (and default values):
- According the task:
-- flush_interval_ms=5000
-- window_ms=1000
-- output_file=aggregator.log
- Additional for debug/experiments
-- verbose=false (if true turns on verbose logging)
-- safety_gap_ms=0 (if not 0 then add gap to avoid late packet problem)

## Other files

- aggregator_log_sample.txt -- example of aggregations for several minutes
- aggregator.log -- here aggregations will be appended by default
- CMakeLists.txt -- cmake main file
- CMakeUserPresets.json -- presets to run/debug from Visual Studio
- conan_install -- script to reset build for Visual Studio
- .editorconfig -- settings for Visual Studio to avoid CR-LF issues
- conanfile.txt -- conan settings
- docker-compose.yml -- docker settings
- Dockerfile -- docker settings
- docker_bash -- script to open docker console

## Threading model and data flow

The app implicitly uses multiple threads but does not require mutexes.
Main thread is main() function which inits and holds all data, runs IXWebSocket and waits for ^C.
IXWebSocket uses callback mechanism, but all callback for the socket run from the same thread, 
so mutexes are not required. When socket is closed, only the main thread works with application 
data to flush it.

binance_aggregator.cpp - main thread, networking and Linux signals are here
Data flow uses combined streams. 
aggregator.* - aggregated data is stored here in a queue of Window objects 
   and every Window object contains simple array of Streams objects (one per symbol).
fixedpoint.* - simple converters to avoid including something as heavy as Boost.
jsonparser.* - bridge to nlohmann
settings.* - .ini file parser and other settings

## Tests

Uses gtest architecture
Run binary 'unit_tests' from folder where file 'fixed_settings_for_test.ini' is placed.
Task required tests are in tests/test_aggregator.cpp and tests/test_jsonparser.cpp.

# Known limitations and TODO-s

- No reconnections, but IXWebSocket allows enabling it via a single option.
- No micro-optimization as requested, probably the JSON parser is probably the biggest bottleneck, 
  it may be simplified, because full functional parser is not required.
- settings.ini may become more standard with JSON version and use more checks.
- No disk-full handling — explicitly out of scope per the task
- Because of requirements there is possible late packet issue if window border
  hits flush time and some packets with small delay are arrived immediately.
  This behavior may be overriden with safety_gap_ms setting.
- If wall time is not sync enough from server time, then app lose more trades.
  This behavior may be fixed with use trade time instead of wall time to define 'past'.
